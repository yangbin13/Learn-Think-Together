## 3. 配置与部署命令

```powershell
git clone https://github.com/yangbin13/Learn-Think-Together.git
cd "Learn-Think-Together/02-源代码/学思同行"
if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
```

实际配置位置为 `02-源代码/学思同行/.env`。配置模板凭证留空；普通 MiMo 默认方案主要填写自己的 `LLM_API_KEY`，其他平台或套餐需同步核对接口地址和模型 ID。示例使用本地 BM25，不要求另填向量模型凭证。配置后再启动。

Windows：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start.ps1
```

Linux：

```sh
sh scripts/start.sh
```

Docker，也从同一源码目录执行：

```sh
docker compose -p thinkmate up --build -d
docker compose -p thinkmate logs -f tutor
docker compose -p thinkmate down
```

正式报告原有未指定项目名的 Docker 命令，在本仓库中统一使用上面的 `-p thinkmate` 版本。源码目录名为中文，显式指定合法项目名可避免由目录名推导项目名的问题；日志和停止命令使用相同项目名。规则依据 [Docker Compose 官方项目名说明](https://docs.docker.com/compose/how-tos/project-name/)。冻结的 compose.yaml 内容保持原样。

默认访问 `http://127.0.0.1:8765`，通过“体验学习工作台”创建独立体验账号。依赖环境为 Python 3.12+、Node.js 22+；Windows 脚本首次安装并构建前端。Docker 配置已提供，最新版本 Docker 构建和容器启动没有重新实测。

## 4. 测试、工具与证据路径

在源码目录运行后端测试与检索评估，再进入其中的 frontend 运行前端测试和构建：

```powershell
.\.venv\Scripts\python.exe -m pytest backend/tests -q
.\.venv\Scripts\python.exe scripts/evaluate_retrieval.py
cd frontend
npm test
npm run build
```

`scripts/` 和 `tools/` 的命令也以源码目录为工作目录，前置条件分别见其 README。GitHub 自动检查工作流在仓库根 `.github/workflows/ci.yml`，已将执行目录和依赖缓存路径调整到嵌套源码位置。
