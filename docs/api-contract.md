# 学思同行 API contract v1

React/TypeScript/Vite frontend, FastAPI/Python backend, LangGraph agent, SQLite durable state. Backend port 8765, frontend dev port 5173; a built frontend is served by the backend on one port. API prefix `/api`. All dates ISO8601 UTC. Frontend default dev proxy `/api` to `http://127.0.0.1:8765`. This contract describes implemented endpoints and fields.

## Authentication

Single install supports multiple students; HTTP-only, SameSite=Lax session cookie. `GET /api/auth/me` -> `{id, username, display_name}` or 401. `POST /api/auth/register` `{username,password,display_name}` -> user and cookie. `POST /api/auth/login` `{username,password}` -> user and cookie. `POST /api/auth/logout` -> `{ok:true}`. `POST /api/auth/demo` -> a private demo student with cookie. Login rate limiting shares the normalized, trimmed/case-insensitive account name used by lookup: 12 failed attempts per IP/account in five minutes trigger 429. Errors `{detail: string}`. Business endpoints require auth; registration/login/demo/logout, health and public configuration do not require an existing session. Unauthorized mutations from an untrusted browser Origin are rejected.

## Catalog

`GET /api/courses` -> Course[]. `POST /api/courses` `{title,description,color?}` -> Course (private to student). `GET /api/courses/{id}` -> Course. Course = `{id,title,description,code,color,icon,assistant_name,is_builtin,document_count,chunk_count,concept_count}`. IDs builtins `data-structures`, `computer-organization`, `operating-systems`, `computer-networks`. Icon = `network|cpu|layers|globe`. Four builtins available to every user. `DELETE /api/courses/{id}` only own custom courses.

`GET /api/courses/{id}/documents` -> Document[]. Document = `{id,course_id,title,filename,status,page_count,chunk_count,error,source_type,license,source_url,created_at,embedding_status,progress,quality}`; status `queued|processing|ready|failed`; embedding_status `lexical|hybrid|lexical_fallback`. `error` and `source_url` may be null. `POST /api/courses/{id}/documents` multipart `file`, `rights_confirmed=true` -> Document with HTTP 202, asynchronous persisted ingestion. Allowed PDF,DOCX,TXT,MD; default limit is 200 MiB (209,715,200 bytes), configurable with integer `MAX_UPLOAD_MB=1..512`. PDF max 2000 physical pages. Public configuration exposes the actual `max_upload_bytes`; the UI uses it for its label and preflight check, with a 200 MiB fallback before configuration arrives. The server writes in 1 MiB pieces and counts actual bytes: crossing its configured limit returns 413 with that limit and removes the partial file, without creating a document/ingestion job. It does not trust the browser check or Content-Length. Empty files return 422, unsupported extensions 415, missing rights confirmation 422. `GET /api/documents/{id}/download` -> authenticated FileResponse. `DELETE /api/documents/{id}` own uploads only. `GET /api/documents/{id}/chunks?page=1` -> `{items:[{id,page,section,text}],total}`; the query `page` is pagination in groups of 20 chunks, while each item's `page` is its actual source position.

`Document.progress` fields vary by processing stage: `{stage,current_page,total_pages,chunk_count,embedding_completed?,embedding_percent,updated_at}`. `stage` is `queued|extracting|chunking|embedding|persisting|ready|failed`. A ready lexical-only document may have embedding_percent=0; ready does not mean vectors are enabled. Complete vector batches are checkpointed and retried without paying for completed batches again.

`Document.quality` is a diagnostic object with optional `{total_pages,text_pages,blank_pages,short_pages,character_count,page_kind,chapter_source,outline_entries,normalization,normalized_characters,ingestion_version,semantic_status,embedded_chunks,semantic_error,semantic_note,warnings:string[]}`. `page_kind` is `physical|logical`. `semantic_error` describes a failed vector call without exposing credentials. Warnings distinguish blank/short pages, text-only indexing and partial semantic fallback. These diagnostics do not claim complete OCR or perfect extraction.

`POST /api/documents/{id}/retry` -> Document, HTTP 202. Only own uploads may retry failed ingestion or ready `lexical_fallback` vectors; queued/processing/already-complete documents return 409, shared seeds return 403, missing source file returns 404. Retry preserves existing valid vector checkpoints.

`GET /api/documents/{id}/preview` -> inline `application/pdf` under the same access checks. Browser navigation to `/preview#page=N` targets the original PDF physical page; the fragment is interpreted by the browser, not the API. Non-PDF returns 415. `GET /api/documents/{id}/pages/{N}/image` -> original page PNG for a ready accessible PDF, with `Cache-Control: private, no-store`, `X-PDF-Physical-Page`, `X-Image-Width` and `X-Image-Height` headers. Image long edge ≤1800, total pixels ≤3,000,000. Out-of-range page returns 422, non-PDF 415, not-ready 409, inaccessible/missing document 404. These endpoints never accept an arbitrary filesystem path.

### PDF caption anchors and personal figure markers

`GET /api/documents/{id}/figures` -> `{document_id,index,items:Figure[]}` for a ready accessible document. `index` = `{status,index_version,current_page,total_pages,figure_count,error,updated_at,notice}`; status `not_indexed|queued|processing|ready|failed`. `figure_count` counts automatic anchors in the job, while `items` includes those anchors and only the current student's manual markers. The read performs no scan or provider call. Not-ready returns 409; inaccessible/missing document 404; anonymous 401.

Figure = `{figure_id,document_id,figure_number,raw_figure_number,number_normalized,caption,caption_text,caption_page,page_start,page_end,page_kind,label,origin,verified,image_mode,page_image_url,source,notice}`. `page_kind="physical"`, `caption_page=page_start=page_end`, `origin="auto"|"manual"`, `verified=false`, `image_mode="full_page"`. `page_image_url` is the authenticated `/api/documents/{id}/pages/{N}/image` endpoint. Automatic `caption_text` preserves the extracted line; limited figure-number normalization retains the original in `raw_figure_number`. These are source-navigation fields, not an image interpretation or extracted knowledge summary. OCR wording can be wrong, and strict caption boundaries can miss real figures. A page image displays the whole physical page, including other figures on that page.

`POST /api/documents/{id}/figures` -> Figure, HTTP 201:

```json
{"physical_page":199,"figure_number":"3-52","caption":"TCP 拥塞窗口的演化（Tahoe 和 Reno）"}
```

This example creates a **personal manual** marker; it does not make the figure an automatic discovery. `physical_page` is a strict integer within the document's one-based page range; `figure_number` defaults to an empty string and allows at most 40 characters; `caption` is required, 1..200 characters and nonempty after trimming. Number/caption strip edge whitespace and reject internal characters with code points below 32. Invalid body/page returns 422. Only ready accessible PDFs with a present source file are accepted; not-ready 409, non-PDF 415, missing source 404. A student may annotate an accessible shared PDF, but that marker is visible only to that student. Placement follows the actual stored page section or its observed common ancestor; ambiguous pages fall back to the document root, without inferring a chapter from the figure number. A new manual marker receives a new ID; this creation endpoint does not promise request-id deduplication.

`DELETE /api/documents/{id}/figures/{figure_id}` -> `{ok:true}` deletes only the caller's manual marker and that node's personal annotation. It preserves the textbook page, chunks, vectors, other markers and learning records. Foreign/missing manual marker returns 404, automatic marker returns 403, not-ready document 409. The UI confirms deletion and explains that this marker's note is removed.

`POST /api/documents/{id}/figures/reindex` -> `{document_id,index}`, HTTP 202. Only own ready uploaded PDFs: shared document 403, not-ready 409, non-PDF 415, inaccessible/missing 404. This is a retry/version-refresh request, not a forced scan. At the current version, `ready|queued|processing` is idempotent and left unchanged; a failed or older-version job is queued with page progress reset. A missing source encountered by the background scan leads to a visible failed job.

`figure_index_jobs` persists one job per document with status, version, page progress, count, attempts and update time; current version is `2026-10-04-caption-anchors-v3`. New PDF ingestion collects caption candidates alongside text extraction. Existing ready PDFs are backfilled by the single ingestion worker; graph reads only consume the stored anchors. Startup requeues interrupted `processing` jobs and queues missing/stale versions. Recovery re-scans the PDF rather than resuming from the last page; page progress is informational. Successful replacement is atomic and deletes only `source_kind='auto'` rows. Stable automatic IDs derive from document/page/normalized figure number; manual markers and personal notes are retained. Failed scans leave ready text/vector learning usable and expose a retry notice. This work performs no OCR, rendering, embedding or visual-model request; it does not replace paid vectors or reconstruct the book.

`GET /api/courses/{id}/graph` retains `{nodes:[{id,label,chapter,mastery,source}],edges:[{source,target,relation}]}` and adds `tree:{root_ids,nodes,total_headings,total_figures}` and `metadata:{mode,total_headings,displayed_headings,graph_limit,sampled,headings_count_excludes_document_roots,warnings,total_figures,auto_figures,manual_figures,figure_index,figure_notice}`. Tree nodes expose `id,parent_id,children,kind,label,heading,depth,order,document_id,page_start,page_end,page_kind,source,concept_id,verified,location_confidence,hierarchy_source,mastery`; current-user annotations optionally add `display_label,study_note,annotation_updated_at`. `kind` also supports `figure`, carrying the Figure fields above, `concept_id=null` and `mastery=null`. Canonical `label`, `heading`, IDs and source fields remain unchanged. The mind-map frontend reads `tree`, not the 180-heading legacy `nodes` sample; there is no separate `mindmap` response field. `total_headings` excludes document roots and figures, and `total_figures` counts visible authorized figure markers, with `auto_figures`/`manual_figures` splitting origin. Tree size depends on the authorized source documents and markers rather than a fixed private-book count.

Natural chapter ordering, observed numbered parents and actual page anchors are preserved. Dense contents-page headings are excluded; mixed contents/body pages retain headings supported by body text. Repairs for prose pseudo-headings and literal slashes apply only to body-extracted PDF paths, preserving surviving node IDs and original chunks; genuine PDF outlines and non-PDF explicit paths keep their hierarchy. Page anchors remain automatically extracted, not manually certified. Edge `kind` separates `structural`, `sequence` and `association`; reading sequence never implies a proven prerequisite. Builtin human-written guide concepts have a separate outline root and no invented PDF mapping. Tree mastery is current-user data: document roots and unmeasured topics are null, measured zero is distinct from unknown, and duplicate heading labels without unique old practice attribution remain null. The existing 180-label exercise cache was not expanded to cover every full-tree section.

### Mind-map evidence and personal annotations

`GET /api/courses/{course_id}/mindmap/nodes/{node_id}/evidence` -> `{node_id,heading,evidence:[{document_id,title,page,section,excerpt,chunk_id,page_kind}],notice,figure?}`. `heading` is the canonical extracted path, even when the student has a display correction. This authenticated read-only endpoint makes no model, embedding or summary request and performs no database writes. For a chapter/section it selects at most three distinct short original excerpts from the selected heading and its actual full-tree descendants, inside the observed page range. Title-only chunks and contents leaders are excluded; excerpt length is at most 320 original characters plus one ellipsis when truncated. `page_kind=physical|logical` distinguishes original PDF physical pages from text/DOCX segments. It returns short text evidence, not automatic diagram/formula interpretation or a complete knowledge summary.

For `page_kind=physical`, mind-map excerpt and node links use the authorized PDF preview with its physical page. For non-PDF `page_kind=logical`, the UI labels the position “逻辑段” and links to `/api/documents/{id}/download` as “下载原文件”; it does not route a logical segment through the PDF preview or imply an original printed page.

For `kind="figure"`, the response has `evidence:[]` and `figure:Figure`, with an explicit automatic/manual source notice. It rechecks the ready document, exact figure ID/physical page and automatic-or-current-user ownership; inaccessible/foreign manual figures return 404. No text excerpt or model-generated explanation is fabricated from the caption. The frontend requests this response and mounts the full-page image only after the selected figure is revealed; hidden recall nodes do not preload source images.

A book root returns HTTP 200 with `evidence:[]` and a notice to select a chapter/section. An original guide node without real textbook mapping also returns an empty list with an explicit notice. A valid heading with no clearly attributable body excerpt returns an empty list, never borrowed evidence from another topic. Course access, ready document status, document ownership and chunk ownership are checked server-side. Anonymous requests return 401; foreign/missing courses or nodes and nodes absent from the current ready-material tree return 404. The validated `4.4.2 地址变换机构` node is `9a4c455934f67c3f7f`; its three excerpt pages are physical 481, 482 and 483.

`GET /api/courses/{course_id}/mindmap/nodes/{node_id}/annotation` -> `{node_id,display_label,study_note,updated_at}`. With no annotation, both strings are empty and `updated_at` is null. `PUT` to the same path replaces both fields; both must be supplied explicitly:

```json
{"display_label":"第七章 操作系统接口","study_note":"我的理解与待核对问题"}
```

`display_label` is a string of at most 160 characters, `study_note` at most 2000; limits apply to the submitted strings before trimming. Both fields strip leading/trailing whitespace; internal text is preserved. Display titles reject Unicode control/format/surrogate characters and line/paragraph separators (`Cc/Cf/Cs/Zl/Zp`), including newlines, tabs and hidden direction controls. Notes allow normal tab/CR/LF, rejecting other `Cc` controls and isolated surrogates. Missing, null, oversized or invalid fields and additional properties return 422 without echoing the supplied text. Whitespace-only strings normalize to empty; if both are empty, PUT deletes the annotation and returns the empty strings with `updated_at:null`. There is no annotation DELETE route. Ordinary saves return the normalized strings and an ISO8601 UTC update time.

Annotations are keyed by `(user_id,course_id,node_id)` in `mindmap_annotations`. GET, PUT and graph annotation fields expose only the current student's record, including on shared builtins and authorized figure nodes. Saving changes no textbook text, chunks, canonical labels, evidence locations, exercise labels or mastery; user/course deletion cascades annotations. A removed/not-ready textbook node is no longer readable/editable. Backend routes permit real textbook roots, chapters/sections, figures and normal guide concepts, but reject guide container roots with no document; the frontend-created `mindmap:course` root is also not a server node. The current UI opens the editor on non-document nodes. Anonymous requests return 401, inaccessible/noneditable nodes or courses return 404, body validation returns 422; untrusted browser origins remain subject to the existing mutation checks (403).

The current UI uses the same backend origin, or Vite's `/api` proxy. CORS permits only the existing development origins `http://localhost:5173` and `http://127.0.0.1:5173`, with credentials and `GET|POST|PUT|PATCH|DELETE`; PUT was added for annotation saves without widening the origin allowlist. See [mind-map design](mindmap-design.md) for expansion, recall and downloads. PNG is the primary offline image format, generated locally at up to 2x resolution with an 8192-pixel side and 16-million-pixel allocation cap; an oversized layout is rejected with instructions to focus a chapter or collapse branches, rather than shrinking below its original size. SVG remains a secondary option. Neither format needs a new endpoint or model request. Local open/close preserves zoom and the clicked position; roots can open/close too. Visited branches remember their expansion and viewport within the component lifetime, without cross-refresh persistence. Those view states are client-side: revealing branches does not update mastery, hidden names remain hidden in both recall export formats, and downloads contain neither original excerpts, personal notes nor page images. “让助教讲解 / 让助教考考我 / 让助教看这张图” populate a chat draft; the student must send it before `/api/chat` requests a model. The image draft carries the chosen document, figure and physical page; one chat POST can cause multiple bounded planning/vision/review provider calls and is not a single billing event.

`GET /api/courses/{id}/overview` -> `{mastery,questions_answered,practice_count,accuracy,weak_concepts:[{concept,mastery,attempts}],recent_activity:[{type,label,created_at}],documents,concepts}`. `GET /api/dashboard` -> `{courses,questions_answered,practice_count,accuracy,study_days,recent_activity,weak_concepts}`.

## Tutor

`GET /api/courses/{id}/sessions` -> `[{id,title,created_at,updated_at}]`. `POST /api/courses/{id}/sessions` `{title?}` -> session. `GET /api/sessions/{id}/messages` -> Message[]. Message = `{id,role,content,citations: Citation[],trace: Trace[],created_at,model?,grounded?:boolean|null}`. Assistant history restores the final citation-validation trace's structured `grounded` value, preserving question-only `null` across refreshes; legacy history without that field falls back to actual citation presence. `DELETE /api/sessions/{id}` -> `{ok:true}`.

`POST /api/chat` `{course_id,session_id?,message,mode:"explain"|"socratic"|"solve"}` -> SSE, starts new session if omitted. SSE lines `event: TYPE\ndata: JSON\n\n`. Events:

- `session` `{session_id}`
- `trace` Trace = `{node,status,label,detail,duration_ms?,grounded?:boolean|null,model?}`; only business-visible decisions/tool summaries, never chain-of-thought. The final `citation_validation` trace persists the exact grounding outcome. A completed `fact_review` trace records the actual review response's model; it does not replace the teaching model on `done` or the saved assistant message.
- `token` `{text}` (validated answer chunks; all teaching modes buffer unapproved drafts before publication)
- `answer_reset` `{reason,attempt?:2}` clears the displayed draft and citations before the one allowed teaching repair attempt. Clients must discard prior draft tokens rather than concatenate the two attempts.
- `citations` `{items: Citation[]}`. Citation = `{id,document_id,title,page,section,excerpt,source_type,page_kind,location_label,chunk_id?,evidence_kind?,vision_model?,model?,uncertainty?}`. Citation IDs correspond to `[1]` answer annotations.
- `done` `{message_id,session_id,model,usage?,grounded:boolean|null,degraded:boolean,final_text}`. Replace the provisional displayed text with the validated canonical `final_text` before saving/exporting a client transcript. `grounded=null` is used for an independently reviewed Socratic question using the student's conditions without introducing a new sourced claim, or the standalone server-side session acknowledgement described below; it does not mean the textbook was verified. New definitions/solutions still require real sources.
- `error` `{message}`

A narrowly recognized, standalone request to confirm continuation of the current course conversation uses the same authenticated, locked and persisted chat route without model/retrieval/tool calls. It returns `done.model="server/session-status"`, zero token usage, `grounded=null` and `citations=[]`; the frontend identifies it as “对话状态确认” / “已保存到当前对话”. This acknowledges receipt and continuation, not upstream model availability. Quoted, unrecognized or mixed knowledge requests do not enter this operational path.

Text citations carry real `chunk_id`; `page_kind=physical` / `location_label=物理页N` refers to the PDF's physical page, `logical` / `逻辑段N` to stable text/DOCX segments. Computed citations use `source_type=verified_computation`, `document_id=tool:<call_id>`, `page_kind=calculation`, `location_label=确定性计算结果`, page=0. Image citations retain the original PDF source_type and actual document/page, carry `evidence_kind=image`, `vision_model`/`model` and `uncertainty`; their excerpt is the actual visual model's recognition, not a fabricated text chunk or deterministic proof.

The server first retrieves up to six real authorized textbook chunks for the current question; simple greetings skip this step. In the real LangGraph loop, the planner then chooses additional search, deep-reading, vision, graph, profile and deterministic tools before evidence check, teaching, citation validation and persistence. Up to four planning rounds, six calls per round, 18 text evidence chunks, two visual calls per turn. `read_material_pages(document_id,start_page,end_page?)` reads up to three actual source pages with separate references. `interpret_pdf_page(document_id,physical_page,question)` only uses an authorized ready PDF page found by retrieval/deep reading or explicitly identified as a physical page by the student. Its scope is local cells, annotations, loads and visible support information. A complex multi-node diagram's complete connectivity is not reliably reconstructed or automatically confirmed: ask the student to check the original page or provide a node-edge table before solving the full structure. It must not emit an allegedly complete connectivity list with only a generic disclaimer.

Deterministic tools include safe arithmetic, `binary_search_trace`, FIFO/LRU, CPU FCFS/non-preemptive SJF, banker safety/request checks, FCFS/SSTF/SCAN/LOOK disk scheduling, IPv4 subnet, Dijkstra and cache timing. `translate_paging_address(logical_address,page_size_bytes,page_table)` validates integer bounds and atomically returns current page/offset/frame/physical address; missing or null page-table entries return `present=false` and no fabricated physical address. `signed_compound_centroid(components:[{area,x,y,label?}],reference?,length_unit?)` supports signed removed areas and an explicit relative direction. `hydrostatic_vertical_plate(width,height,top_depth?,density?,gravity?,hinge_depth?)` uses SI units; moment is returned only about a provided hinge reference. These tools verify the supplied numerical model, not unprovided geometry, hinges, support reactions or engineering safety. Only-heading chunks cannot support factual answers. Planner emits complete tool calls or DONE; it does not produce the final teaching answer.

`binary_search_trace(values,target,occurrence="any"|"first")` accepts 0–256 nondecreasing finite numeric values and a finite target, with absolute values at most 10^15; booleans, numeric strings and unordered input are rejected rather than sorted. It uses zero-based closed intervals and a floor midpoint. `comparison_count` counts one three-way target-versus-midpoint probe per step, excludes the O(N) order check, and has `worst_case_probe_bound=len(values).bit_length()` (0 for empty input). `any` returns an encountered equal value without promising the first duplicate; `first` continues left and guarantees the leftmost match. Returned input copies and step traces use extra storage; the tool's memory must not be cited as the textbook search's O(1) auxiliary space.

The last 16 persisted messages provide multi-turn context. Historical citation markers and old location claims are removed from planner context. Each prior assistant message's real text sources are reauthorized through SQL; only surviving current evidence is rebound to current citation IDs for teaching, including sources from older messages when the latest assistant message had no citations. Deleted, foreign or evicted sources are removed without inserting copyable internal placeholders. Old computations and visual results require a fresh check when needed. Numerical citation markers `[1]`, `【１】` and `［1］` are normalized to `[1]` outside code spans/fences; code-array indices, identifiable numerical containers and standalone numerical containers in table data columns are preserved and excluded from source validation/rebinding. Explicit Source/Citation columns still support reference markers. Ambiguous mathematical data should use inline code.

Image history has a separate context policy. Before planning, every prior assistant message containing image citations is replaced by a source-location notice. For teaching, an old image message is replaced when its document/page intersects a page the current turn has legitimately attempted to reread after access and page checks. Only newly returned `image_evidence` marks a reread successful; rendering/vision failure leaves it explicitly unconfirmed. Replacement is message-level: a mixed A/B message loses its old prose but retains both page locators and distinguishes successfully reread pages from unconfirmed ones. Ordinary text messages and separate unrelated page/document messages remain in teaching context, with text sources reauthorized and rebound. Persisted database messages are unchanged. A historical locator is neither citable evidence nor page-access authorization.

Invalid source IDs/locations, leaked internal placeholders and unsupported claims that a textbook or an image provided the answer trigger at most one controlled teaching repair. A second invalid strict-agent draft is rejected. The API then attempts the isolated unverified learning recovery described below; the rejected draft itself is never saved as approved. Truncated/content-filtered outputs and provider failures remain rejected inside the strict agent and are never accepted as repaired JSON or a complete answer. An honest response explaining missing evidence can finish with `grounded=false`. No hidden planning/reasoning content is emitted. A failed/interrupted turn may retain the student's question. Client abort/disconnect closes the producer and upstream HTTP stream, and releases the session lock; provider billing cancellation depends on its server policy. Unconfigured provider returns an explicit error and never a fake AI response. Citation validation proves source identity/position and bounded policy compliance, not automatic semantic truth.

High-risk teaching (actual computation results, solve/Socratic mode, strong logical assertions, conditions, diagrams/tables or multiple explicit questions) also receives one independent model fact review per draft. Its input is the original question/context, only the authorized citation cards actually used by that draft, actual tool arguments/results and draft, never a benchmark answer. It no longer receives every retrieved `state.citations` card: an unused source cannot substantiate a different card's local claim, and source text is not itself an assertion in the draft. Source-support review concerns the actual cited excerpts rather than presumed whole-book knowledge. Strict `{approved,issues}` output checks numbers/units/step arrays, necessary versus sufficient conditions, internal contradictions, unprovided assumptions/reference points, source support and question coverage. Issues enter the same single repair budget; a failed or invalid review is never implicit approval. `fact_review` trace labels this a local model check, not a deterministic proof or correctness guarantee. Socratic review also rejects a question that leaks the final solution or introduces unsupported new definitions.

By default, `mode="socratic"` generates a single-step draft through a strict JSON object with exactly two string fields: `feedback` is limited to 240 characters and `question` to 140 characters before trimming. Brief feedback is encouraged within 80 characters. Duplicate/additional fields, surrounding prose/fences, nonstrings and hidden analysis content are rejected. Feedback may be empty and cannot contain a question mark; the nonempty question has one question mark, ends as a question and cannot append an explanation task. The server assembles these fields into ordinary teaching text; the student receives the validated prose rather than the internal JSON object. All Socratic teaching is buffered until source/policy checks and fact review pass. An explicit current no-question request such as `不要继续提问` selects direct teaching; quoted, negated, hypothetical and reported commands do not automatically opt out.

The first single-step feedback must be empty. Feedback becomes eligible only when the raw persisted conversation ends in the current nonempty user message immediately following an assistant message whose final unquoted, non-code text is a real question. Detection does not skip intervening messages to find an older question or treat quoted/code questions as the active prompt. Eligibility is not semantic approval of feedback. An explicit, unquoted current-user request for a direct answer or several guiding questions opts out of the two-field single-step format; it remains in Socratic mode with source checks, fact review and buffered display. A single question mark cannot prove a single cognitive task or absence of leaked solutions; structured output and a model approval do not replace independent teaching review.

Question coverage omits explicit source-locator fragments such as the original PDF physical page and an adjacent document identifier, including possessive bridges such as “文档ID…的原PDF物理页…”, from its teaching-term checklist; the original message remains intact for planning, page authorization and teaching. Actual requests to explain PDF/ID still count as subject requirements. Fact-review instructions also separate the requested figure's visual observations from additional explanation: observations require the matching real image document/page; supplemental concepts may use other authorized evidence from the same course when clearly distinguished and supported. Asking to inspect/cite a particular page does not alone impose exclusive sourcing; only an explicit “只用/仅限/do not use other sources” constraint narrows all available sources. Wrong figure/page, unsupported image claims, unsupported citations and supplementation disguised as visible image content remain grounds for rejection. Natural statements such as “缺少来源” and “缺少依据” both permit an honest evidence-limited response; neither creates a successful image source. These software checks do not guarantee that a real model answer will pass or be semantically correct; real model cases require separate validation; automated checks do not replace it.

`done.usage` contains the sum of independent planner, vision, teaching and fact-review request token statistics, potentially from different configured models, including a discarded teaching attempt if one occurred. SiliconFlow streaming usage is a cumulative snapshot repeated on successive chunks: the provider adapter records only the last nonempty snapshot once per request. Usage is not the platform's account balance or currency bill and does not include separate embedding calls. `done.model` and the saved assistant message's `model` remain the actual teaching response model, except for the explicit `server/session-status` acknowledgement and `server/learning-continuation` identities; completed `fact_review` traces identify the actual reviewer in their `model` field, and visual model identity is carried on its image citations.

`GET /api/config/public` -> `{provider,model,quiz_model,review_model,configured,embedding_model,agent_framework,vision_model,vision_enabled,max_upload_bytes}` (no API key/base with secrets). `quiz_model` and `review_model` are the effective configured textbook generator and reviewer; each falls back to `model` when its override is empty. They are configuration values, not proof of completed calls or the actual identity of any historical quiz. `max_upload_bytes` is the configured byte limit for one uploaded file, independent of model availability. `configured` only means nonempty key/model, not live validity. A blank `EMBEDDING_MODEL` or disabled `EMBEDDING_ENABLED` uses `embedding_model="disabled / BM25"` and makes no ingestion/query embedding call, even if old document vectors exist. `vision_model` is null when disabled; enabled is a configuration flag, not proof of availability. `GET /api/models` -> `{models:[{id}],current}` available provider chat models excluding recognized embedding/audio/image-generation entries, authenticated. Routing uses server environment configuration, no client-side key. `/api/health` (alias `/health`) checks database readability; `/config/public` is a public configuration alias.

`LLM_QUIZ_MODEL` optionally routes only custom-course textbook question generation to another model on the same `LLM_API_BASE/LLM_API_KEY`; empty uses `LLM_MODEL`. Builtin 408 quizzes use the curated bank without generation/review model requests. `LLM_REVIEW_MODEL` independently selects answer fact review and textbook-quiz review, also falling back to the main model when empty. Teacher/planner use the main model; an empty `VISION_MODEL` also uses the main model. Embeddings remain `BAAI/bge-m3` when enabled: optional `EMBEDDING_API_BASE/EMBEDDING_API_KEY` route only embedding requests to a separate provider, while omitted values preserve the previous shared-endpoint behavior.

`LLM_QUIZ_THINKING` and `LLM_REVIEW_THINKING` default to false and independently control their respective generation/review calls. On a SiliconFlow endpoint the adapter sends `enable_thinking`; on MiMo it sends native `thinking.type` explicitly. Other compatible endpoints do not receive these provider-specific options. These flags do not enable thinking for ordinary teaching/planning. Enabling either may increase latency and cost; no quality or price advantage is implied.

`LLM_QUIZ_THINKING_BUDGET` and `LLM_REVIEW_THINKING_BUDGET` each accept strict integers in `128..32768`, default `1024`; invalid configuration is rejected. The respective budget is included as `extra_body.thinking_budget` only when that request's thinking is enabled on SiliconFlow. It is separate from the `max_tokens` output budget, `LLM_MIN_OUTPUT_TOKENS` and actual usage, not a currency cap or an observed consumption value. Output allocation and returned usage are separate; this deployment uses MiMo, and earlier provider experiments are not current acceptance results.

`LLM_JSON_MODE_ENABLED=true` requests `response_format={"type":"json_object"}` for single-step drafts, quiz generation and model review. Tool planning and ordinary streamed teaching do not use this JSON-body format. If a provider does not support it, users may explicitly disable the setting; strict local parsing, source and semantic gates remain active. The adapter can make one explicit format recovery for supported JSON-transport failures, using a strict plain JSON request; truncation, filtering, quota and local protocol gates remain unchanged. Actual returned usage is accumulated across that recovery. JSON mode constrains structure, not semantic truth or educational suitability.

`AsyncOpenAI` is configured with `max_retries=0`, disabling implicit SDK network retries of potentially paid requests. This does not remove the existing one explicit content-repair budget, and unavailable/invalid review still stops instead of triggering another teaching draft. The setting change alone does not establish that any previous live attempt actually used an SDK retry; one application POST may still include independent planner, visual, teacher and reviewer requests.


### Honest chat recovery and execution deadlines

The strict teaching execution runs inside `asyncio.timeout(settings.provider_timeout)`, default 90 seconds. Its internal rejection or timeout invokes one ordinary completion with a separate budget `min(30, provider_timeout)` seconds. It receives only necessary student questions, never the failed draft, internal error text, old assistant answers or source markers. Previous student errors provide context for their correction; a verdict must judge the last current attempt without attributing corrected old errors to it. It returns no textbook/image/tool citations and labels that this turn has not verified those sources. If the completion is unavailable or unsafe, the service emits `model="server/learning-continuation"`, empty citations, `grounded=false` and `degraded=true`, explicitly identified as a service continuation. Real generated recovery preserves the actual response model. Trace status `degraded` records the attempted and recovery paths. 402/429, authentication/validation boundaries and cancellation retain their existing meanings. These are execution budgets, not a promise of instant response or proof of knowledge correctness.

## Practice / review

`POST /api/courses/{id}/quizzes` `{topic?,difficulty:"基础"|"进阶"|"挑战",count: 1|3|5}` -> `{id,title,questions:[{id,type:"single_choice",stem,options:[{key,text}],concept,difficulty,concept_measured?,concept_notice?}],created_at,source,source_kind:"curated_bank"|"textbook_generated",generation_model:string|null,review_model:string|null,draft_answers:{},draft_version:0}`. `count=1` supports a quick check after a multi-question generation/review attempt is rejected for excessive output; `3` and `5` remain focused and chapter-sized practice. `source_kind` is chosen by the server's actual course path, not by interpreting a source sentence: builtins always use the curated human-written bank; uploads to a builtin do not alter this path. When requested count requires adjacent difficulty or other-topic questions, `source` explicitly discloses supplementation and topic match count. Arbitrary textbook/topic generation is available inside a student's own custom course after uploading a ready textbook; generated answers remain model outputs requiring teacher review. Never return correct answers, explanations, private `source_ids`, or source excerpts that could reveal answers before submission. Draft answers are the student's choices, not the answer key.

Creation also returns `generation_model:string|null` and `review_model:string|null`: for textbook generation they are the last approved generation/review responses' actual `response.model` values, not the requested configuration or an earlier rejected draft. Missing response identity remains null. Builtin-bank creation returns both null because it makes no model call; `source_kind=curated_bank` identifies that path. These two fields are creation-only metadata, not currently persisted in quiz rows or included by load/history. Clients must not substitute public configured models for historical actual identities.

For a custom quiz without `topic`, default evidence is sampled across actual textbook chapter/section content; source chunks remain unchanged. Structured documents exclude front matter, prose pseudo-headings and ending pages from this default learning view. A genuine PDF outline with no usable body returns 409 before any generation/review call; unstructured ordinary text remains supported. An explicit topic follows authorized course retrieval instead of this default view.

Generated concepts are checked against each cited chunk's canonical textbook path/aliases and actual ancestors. Multiple sources must share the same unique supported label; a global course vocabulary match is insufficient. Ambiguous same-name headings cannot share concept mastery. A physical page can span adjacent sections: a later section's opening page uses a reliable common ancestor rather than claiming paragraph-level leaf attribution. When all sources lack a unique attributable label, the question can pass content review with `concept_measured=false` and a public `concept_notice`; it still receives a quiz grade and, if wrong, a mistake record, but contributes neither mastery attempts/correct nor weak-concept plan evidence. `true` means eligible attribution, not an already graded or teacher-certified concept. Semantic/source-scope rejection allows at most one regenerated group and another independent review; protocol/service failures and a second rejection do not persist a quiz. Source ownership/readiness and concept scope are rechecked after model awaits before insertion.

The local reviewer receives original evidence fragments only for the union of the current candidate questions' `source_ids`; each question must still be supported by its own IDs rather than borrowing another question's evidence. It records each question's condition completeness/source support and all four options' `correct|incorrect|uncertain` verdicts with reasons. Approval requires one uniquely supported correct option consistent with the saved key. A complete rejected review with explicit issues, including uncertain options, can use the one semantic repair; `approved=true` combined with uncertainty is a contradictory protocol result and stops. Request `max_tokens` values are not universal online hard caps: the Provider may apply its configured model-specific minimum output budget, according to that configured adapter. A complete review ledger remains a model check, not teacher certification.

`GET /api/quizzes/{id}` -> public quiz fields plus `submitted`. While unsubmitted it returns `draft_answers` and `draft_version`, without `result`, correct answers or explanations. After submission it returns the authoritative graded `result` and omits both draft fields; both recovery and successful submission restore UI choices from the returned graded `results[].user_answer`, not an older draft or local selection. Anonymous requests return 401; another student's quiz or an inaccessible custom course returns 404. The creation-only `generation_model/review_model` fields are not returned here; existing records have no persisted values for them.

`PUT /api/quizzes/{id}/draft` replaces the complete answer snapshot and returns `{draft_answers,draft_version}`. There is no separate GET `/draft`; restoration uses GET `/api/quizzes/{id}`. Example body:

```json
{"answers":{"question_id":"A"},"expected_version":0}
```

Both fields are required and additional fields are rejected. `answers` is a map with at most five entries; each key must identify a question in this quiz, and each value must be exactly `A|B|C|D` and an actual option for that question. `{}` is allowed to clear an unsubmitted draft. `expected_version` is a strict integer in `0..2147483647`: booleans, strings, fractions and out-of-range values return 422. Invalid questions/options, oversized maps and invalid body shape also return 422. Request-body parsing and field/type/range checks precede the helper transaction. Ownership, submission state, actual question/option membership, version comparison and writes are checked within `BEGIN IMMEDIATE`, sharing the serialization boundary with grading. A submitted quiz returns 409 for a valid draft-save request. Identical answers return the current snapshot/version without an increment, even if the supplied valid version is older. Different answers require the current version; a mismatch returns 409 without overwriting. A changed snapshot increments the version once; at the maximum version it returns 409 rather than overflowing. Draft writes do not grade, update mastery/mistakes, record completed practice activity or request a model. Schema migration adds `quizzes.draft_answers` and `draft_version` without replacing existing quiz records.

The frontend serializes snapshots per quiz using the last acknowledged version. A failed save is surfaced and does not permanently reject later queued tasks. Recovery explicitly offers “读取已保存作答” (replace local choices from a fresh GET) and “保存本页作答” (fetch the current version, then attempt to overwrite with the local snapshot). If another update wins that race, 409 still applies; if already submitted, either recovery shows the graded result. Saving/error states show an unsaved notice and register a browser `beforeunload` warning while unsubmitted. `keepalive` is used for issued draft requests, but an in-memory queue is not a durable offline queue and cannot guarantee all queued snapshots survive an immediate refresh. Internal SPA navigation is not universally intercepted by `beforeunload`.

`POST /api/quizzes/{id}/submit` `{answers: {question_id: "A"}}` -> `{score,total,correct,results:[{question_id,correct,user_answer,correct_answer,explanation,concept,citations,concept_measured,concept_notice}],weak_concepts,next_action,unmapped_question_count?,measurement_notice?}`. Scores include all quiz questions; concept statistics only include attributable questions. An unmapped count/notice is present when one or more questions have `concept_measured=false`; `weak_concepts` excludes them. Existing curated/legacy questions without a flag retain their existing measurement behavior. Course overview and dashboard `accuracy` derive from measured mastery counters, so they can differ from the percentage for an individual quiz containing unmapped questions. For an unsubmitted quiz, missing answers are marked 未作答; foreign question IDs and choices outside A/B/C/D return 422 without consuming the quiz. Submission is transactionally idempotent, including concurrent requests, mastery and mistake records; repeat submissions return the saved graded result. The UI waits for its draft queue to settle, then submits the current local answer payload; queue settlement does not prove every prior draft save succeeded. If another page already submitted, the returned original graded result also replaces this page's selected radio answers. Current regression checks preserve the authoritative graded choices across repeat submissions; actual model, textbook and UI behavior needs validation in its target environment. Another student's quiz returns 404.

`GET /api/courses/{id}/practice` -> `{quizzes:[{id,title,score,total,created_at,submitted}],mistakes:[{id,concept,stem,user_answer,correct_answer,explanation,created_at,resolved}]}`. `POST /api/mistakes/{id}/resolve` -> `{ok:true}` sets `resolved=true` for the caller's mistake. The UI calls this archiving (“我已理解，归档此题” / “显示已归档”); it does not change graded correctness or measured mastery. Dashboard maps activity type `practice` (and legacy `quiz`) to “章节练习”, `review` to “复习任务”, and `plan` to “复习计划”.

`POST /api/courses/{id}/plans` `{days:7|14|30,daily_minutes:15..180,goal?}` -> Plan = `{id,goal,days,daily_minutes,items:[{id,day,title,description,concepts:string[],minutes,completed}],created_at,basis}`. Rules prioritize measured weak concepts, then existing concepts matched to the goal. Remaining custom-course labels follow depth-first traversal of the authorized actual textbook tree, filtered to the existing concept catalog and de-duplicated, rather than hash-ID order. Builtins retain natural chapter/ID ordering; a missing reliable structure does not invent a textbook sequence. Optional authorized textbook retrieval separately searches up to four meaningful goal intents, maps each intent's primary hit to its most specific existing section label, and avoids adding every ancestor/unrelated lower-ranked neighboring section. Direct label matches are preserved. Unmatched goals or retrieval failure are disclosed in `basis` and fall back to offline rules/direct label matching. No plan LLM call is made and no mastery is invented or changed; nonempty goal retrieval may call the configured embedding service, so plan generation is not universally cost-free. Interval review on days 6/9/12… revisits previously introduced weak/goal concepts instead of an unrelated new topic; `basis` lists the actual review days. Daily item minutes equal the input budget. No practice means unknown mastery, not zero or complete mastery. `GET /api/courses/{id}/plans` -> Plan[]. `PATCH /api/plans/{id}/items/{item_id}` `{completed:boolean}` -> Plan, with persistent completion and idempotent activity recording. `GET /api/export?course_id={id}` -> Markdown attachment of own conversations/practice/plans; omitting course_id exports all accessible courses' own learning records, without secrets or unsubmitted answers. This learning archive is not a full backup of private textbooks, figure markers, personal map notes or unsubmitted drafts.

## Seed data contract

Root agent creates `content/catalog.json`: list of course objects with ids/title/code/description/assistant_name/color/icon, `documents:[{path,title,license,source_url?,source_type}]`, `concepts:[{id,label,chapter}]`, `edges:[{source,target,relation}]`, `questions:[{id,stem,options:[{key,text}],answer,explanation,concept,difficulty}]`. Paths relative repo root. Original Chinese 408 handbooks in `content/408/*.md`; external licensed textbooks may be added with provenance. Backend startup ingest all seed docs locally; no paid LLM/embedding calls for seed ingestion by default. Seed graph concepts have evidence text mapping, heuristic extraction for custom courses labeled automatically extracted.

## Access and operational boundaries

Custom courses, uploads (including private uploads to a builtin), sessions, quizzes, mastery, mistakes, plans and mind-map annotations belong to their student. Shared seed textbooks are read-only; personal annotations do not rewrite them. Inaccessible objects return 404; attempts to delete shared/builtin objects return 403. Concurrent generation in one session, deletion of an actively generating session/course and duplicate ingestion retry return 409. Non-chat provider failures can return 502. Chat internal failures attempt honest recovery; quota/rate-limit failures remain safe SSE errors. Cancellation is not swallowed or saved as a complete answer. Parameter validation returns 422 without echoing request secrets; SQLite availability errors return 503.

Run one Uvicorn worker: ingestion and caption-index jobs are durable/recoverable but distributed worker leases are not implemented. Text PDF ingestion is supported; whole-book OCR for scanned PDF is not implemented. A scanned book with an existing hidden OCR layer can be indexed through that layer, with its existing recognition errors. Caption extraction, full-page viewing and on-demand visual interpretation are separate paths. Visual checks are bounded and may misread; visual reading quality needs separate validation with the target model and materials. Tests with isolated databases/explicit FakeProvider verify software boundaries; real textbook/model scenario results are separately recorded and do not imply universal answer accuracy.
