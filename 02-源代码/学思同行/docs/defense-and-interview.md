# 答辩与面试：值得讲的真实工程亮点

## 介绍项目

“学思同行是一个可配置的专业课助教。学生上传教材后，系统按课程独立检索和建立知识关联；助教通过LangGraph选择教材、学习记录和计算工具，回答可以回到原文。答疑之后可以练习、看到错题并形成复习计划，整条流程的记录会保存。408四科是内置参考课程，其他专业也可以创建。”

不要把它叫做已完成大规模教学验证的平台，不声称一定提高考试分数。不要用“多Agent”包装一个有工具的Agent。项目内确实使用LangGraph工具决策循环；练习判分、权限和学习记录由普通业务服务负责，两者的边界清楚。

## 常见追问与回答要点

**为什么不直接用普通RAG？** 普通检索一次再生成难以决定何时重检索或调用计算。我们让模型基于工具结果继续决定下一步，但以有限轮次和证据上限控制费用。真正价值是按任务调用工具和保留学习状态，不能宣称Agent在所有问题上比RAG更准。

**知识图谱在哪里发挥作用？** `expand_concepts`返回课程内关联知识点，模型可用邻近概念重新检索，帮助串联问题。408结构是人工编排，自定义课是教材标题提取和相邻关系；它是课程概念关联图，不是已经审核全部事实的专业知识图谱。正式先修关系和多跳语义事实抽取是扩展方向。

**如何减少幻觉？** 课程/学生范围过滤、实际资料片段、强制引用编号、只允许本次证据、工具验证、证据不足提示。编号存在不等于引用支持全部结论，因此还需要人工或独立评估事实支持度；不把`grounded`当作100%正确。

**中文检索怎么做？** Jieba与字符bigram处理术语，BM25保留精确匹配。启用语义嵌入后用余弦检索，再用RRF合并排名，避免直接把不同比例的分数相加。种子默认词法，不声称种子已全量向量化；失败可降级并在轨迹中说明。

**如何隔离用户？** 服务端用Cookie会话识别学生，资源查询每次验证所有者，公共种子只读，私人教材过滤user_id与course_id。测试不止看前端列表，还请求他人的资源ID确认无法读取。

**如何证明计算可靠？** 页置换按每次引用保存命中/缺页/淘汰/页框状态，子网用ipaddress处理边界，Dijkstra拒绝负权，算术只解释白名单AST。模型说明题目，确定性工具计算；如果模型把问题参数读错，工具也可能得到对错误模型正确的结果，因此要让输入假设可见。

**持久化的边界？** 已完成会话和练习持久保存，提交幂等，摄取状态可重启恢复；不是任意Agent节点跨进程续跑。SQLite适合单实例；多实例需数据库、分布式队列和持久checkpointer，不应拿后续方案当当前成果。

**你的个性化学习是怎么来的？** 来自实际作答与概念统计，薄弱点用于推荐练习与安排计划。没有学习证据就是未测；这是透明启发式，没有训练个性化模型，也没有临床或教育实验的成绩提升证明。

**如何评价效果？** 分开评估业务正确性、检索命中、真实模型行为、浏览器流程。结果在`docs/validation`中可复现。24条自编检索问题是小型烟测，不能当成任意教材问答正确率；公开报告列清楚规模、运行环境和限制。

**当前模型和失败处理？** 当前教学、规划、出题、审核和视觉统一Mimo。简单任务已有真实正文时省去额外规划；严格Agent失败后隔离旧草稿，尝试说明教材/工具未核实的通用教学。教学执行默认90秒期限，恢复最多30秒；额度、限流、取消和权限边界保留。当前验收与旧模型历史分开，见 submission-report.md 与 test-cases-final.md。

## 简历可用表述

- 独立实现React/TypeScript + FastAPI的可配置专业课助教，支持授权教材导入、四科408参考助教及跨专业课程，贯通答疑、练习诊断与复习留存。
- 基于LangGraph实现有上限的工具决策循环，集成中文BM25/可选语义向量检索、教材引用和确定性算法校验，提供可查看的执行摘要与明确失败反馈。
- 设计SQLite学习状态与用户课程隔离，完成异步摄取状态恢复、测验提交幂等、错题与计划持久化；用自动测试、真实模型与浏览器验证分别记录工程证据。

数字请使用当前验收报告实际结果，不填写未测用户数、并发量、通用正确率或“提效XX%”。若将来在真实课程做盲测，可增加教材规模、问题难度分布、事实支持率和学习效果等指标。
