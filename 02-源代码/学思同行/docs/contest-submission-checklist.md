## 2. 命题二与评分关注

命题二 P26—P29 要求知识点讲解、步骤化解题、错因诊断、练习与复习规划，形成“追问—纠错—再讲解”的对话闭环，并保留学习或练习记录。关键结论可通过真实教材引用、规则或测试样例核对。提交演示应覆盖学生能持续完成学习任务的实际流程。

| 评审项 | 分值 | 可审阅的证据 |
| --- | ---: | --- |
| 落地价值 | 30 | 明确课程学生与助教的使用需求；真实教材对齐、连续学习与可复核计算。 |
| 任务闭环与稳定性 | 25 | 输入、处理、输出与兜底；三种教学模式、多轮纠错、练习反馈、保存与恢复。 |
| 工程质量 | 20 | 模块与调用链、依赖版本、部署命令、日志和异常处理、可复现测试。 |
| 交互与体验 | 15 | 及时反馈、可理解回答、可展开来源、学生操作顺畅。 |
| 安全合规 | 10 | 数据授权、权限隔离、必要收集、脱敏与真实来源。 |

参赛注意事项 P100—P104 要求参赛队伍独立完成，允许开源框架、公开模型和第三方工具，但应说明来源、用途与使用方式。报告应陈述实际业务实现和复用边界，不冒用第三方成果，不捏造参赛成员身份或教学效果。

## 4. 源码与提交文件的归档核对

源码按当前磁盘文件收集，包含本次未提交 Git 的业务模块、测试和前端构建产物。依赖目录通过锁文件安装，独立演示账号在启动后创建。

归档核对项目如下：

1. 清单内每个文件与当前源文件的大小和 SHA-256 一致，ZIP 可完整解压，路径无越界。
2. `.env`、实际凭证、本机账号表、SQLite、用户上传、私有验证原始数据、日志、缓存、`.git`、`.venv`、`node_modules` 和旧 ZIP/视频草稿不进入作品源码。
3. `.env.example` 的密钥值留空；配置项名称和使用说明可以保留。测试中专用的假密码或占位值与真实凭证分类处理。
4. 对归档内容再扫描实际配置凭证及常见密钥格式；DOCX 内部 XML、PDF 提取文本和嵌套归档分别检查，输出只记文件位置与风险类别。
5. 只带当前精选验收摘要，排除私有教材原文、未脱敏快照和无关历史调试文件。
6. 最终视频与当前技术报告由提交目录直接定位，报名表与作品源码分开保存。

报名原件含个人信息，仅供赛事报名提交，不嵌入公开源码。手册 P93—P98 所列报名字段与现有模板字段不完全相同；缺失身份字段须由参赛者或已提交报名信息确认，不编造或公开个人信息。作品六项材料与平台报名办理分别核对。
