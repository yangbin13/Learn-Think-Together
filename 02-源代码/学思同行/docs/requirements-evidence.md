# 学思同行：需求来源与开发验收基线

本文件区分赛事硬性要求、报名表已经声明的方向、用户新增要求与实现边界。证据源为工作区提供的三份 Word 原件。Word 定位对应 `docs/source-materials.md` 的 XML 段落/表格编号，不冒充渲染后的页码。姓名、手机号及含姓名的文件标题已脱敏；真实报名信息由参赛者向组委会提供，不进入应用与源码。2026-10-11 的最终材料、测试和实现情况见 `submission-report.md`、`test-cases-final.md` 与 `submission-checklist.md`。

## 2. 赛事硬性功能要求

| 编号 | 要求与证据 | 最低可验收行为 |
| --- | --- | --- |
| R01 | 知识点讲解；手册 P0026—P0027 | 学生选择一门课，输入概念，得到按课程资料解释的回答。来源可打开查看文档名、页码或章节以及实际片段。 |
| R02 | 题目步骤化解析；P0027—P0028 | 题目解析包含条件、步骤和结论；不能只给最终答案；能说明适用条件与关键规则。 |
| R03 | 错因诊断；P0026—P0027 | 输入学生答案或提交练习后，指出具体错在何处，区分概念混淆、步骤遗漏、计算错误等，并给出下一步纠正任务。 |
| R04 | “追问—纠错—再讲解”闭环；P0028 | 同一会话问“为什么”、指出不理解或回答错误后，模型收到先前对话和学生反馈，再解释前一个知识点；纠正不依赖重新复制整段题目。 |
| R05 | 个性化练习；P0027 | 围绕薄弱知识点生成或推荐练习，支持提交、反馈、再练；学生提交前不泄露答案。练习不得冒称来自真实历年真题。 |
| R06 | 阶段性复习计划；P0027 | 依据真实练习、错因、可用天数输出分阶段计划；暂无记录时明确使用初始计划，不能伪造学生掌握度。 |
| R07 | 学习记录或练习记录；P0028 | 会话、练习尝试、反馈持久化；刷新后可继续；允许查看和删除，课程及学生间隔离。 |
| R08 | 教材引用、规则校验或测试样例验证关键结论；P0028 | 引用来自本次真实检索片段；可验证算法题用有限规则/样例校验；资料不足或结论无法验证时明确边界并请学生补充材料。只显示“可信”标签不足以验收。 |
| R09 | 可演示、可复用、可试点推广；P0018 | 新建课程、上传材料、索引、提问、练习、复习形成完整操作链；提供本地部署与演示方式。 |
| R10 | 正常、异常与边界场景稳定闭环；P0084 | 空问题、空课程、解析失败、扫描版缺文字、无匹配资料、模型失败都有清晰反馈；不静默伪造正常输出。 |

## 4. 提交要求与时间边界

中兴赛道的交付清单来自手册 P0045—P0051：

1. 可运行作品：可访问链接、可执行包或部署说明；登录时提供测试账号或演示模式。
2. 技术文档：架构图、模块、核心功能、技术路线、部署方式、依赖环境、配置项。
3. README：环境配置、依赖安装、启动命令、运行方式、测试方式、常见问题。
4. 至少 10 条用例：正常、异常、边界均覆盖。
5. 3—5 分钟演示视频：核心功能、主要流程、实际效果。
6. 合规说明：数据来源、隐私保护、真实个人信息使用、脱敏方式。

手册 T001-R004 要求中期方案包含目标用户、核心流程、数据来源、工具清单、最小 Demo。T001-R005 指定初赛线上试用、统一挑战用例、复现抽检、文档/合规检查。T001-R006 指定决赛每队 6 分钟作品演示、6 分钟答辩，并现场抽取 1—2 条挑战用例。

手册 P0080 明确赛程暂定，具体以组委会通知为准。表格写有 7 月报名、8 月中期、9—10 月开发/初赛、10 月决赛；材料未提供具体截止日，不能自行推断 2026 年 10 月的提交日期，也不能声称已向组委会提交或报名状态已审核。

## 5. 建议的开发范围与验收用例

以下为比赛要求对应的实际工程范围；具体测试边界以最终验收为准：

- 课程层：四门 408 独立助教、创建任意课、用户授权上传 PDF/文本/Markdown/DOCX；文件解析失败与扫描版提示；资料版本、章节/页码、索引进度。
- 检索层：课程范围过滤、中文字符/章节分块、关键词与向量混合检索；可选知识点关系扩展；返回真实引用及检索不足判定。
- 工作流层：明确讲解/解题/纠错/练习/复习路由，状态记录与工具执行过程；受限的计算/样例验证；模型输出与确定性规则反馈区分。
- 学习层：课程内会话、练习尝试、错因与薄弱点、基于记录的复习计划；真实状态持久化；导出与删除。
- 工程层：后端服务、独立前端、结构化数据库与迁移、配置管理、可观测日志、测试、部署/文档。是否使用 LangGraph/LangChain 等框架应由主工程根据真实调用需要选定。

建议至少覆盖这些挑战用例，并记录实测状态：

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| TC01 | 数据结构助教询问复杂度 | 对应课程真实片段引用，解释结论的适用条件。 |
| TC02 | 组成原理计算题 | 条件→公式/规则→步骤→结论；有规则/计算校验时显示实际结果。 |
| TC03 | 网络协议概念比较 | 只检索网络课，展示具体来源；不会串入另一门的回答缓存。 |
| TC04 | 操作系统问题追加“为什么” | 继承上一轮上下文，再讲解。 |
| TC05 | 学生指出答案矛盾 | 重新核对资料，说明修正或保留理由，保留完整记录。 |
| TC06 | 提交错误练习答案 | 有具体错因、解释、下一步再练，记录本次尝试。 |
| TC07 | 基于错题生成复习 | 计划对应真实薄弱点，空记录不显示虚构掌握度。 |
| TC08 | 上传另一专业课程 | 新课程索引与助教可运行，原四门记录不串扰。 |
| TC09 | 刷新/重启应用 | 课程、资料、会话、练习尝试保留。 |
| TC10 | 空输入/空课程 | 明确提示补充问题/资料，符合输入—处理—输出—兜底。 |
| TC11 | 无关问题/未收录知识 | 明确未检索到足够教材证据，不编造教材页码。 |
| TC12 | 非支持文件/损坏 PDF/空文字扫描 PDF | 拒绝或明确处理限制，不误报索引成功。 |
| TC13 | 两门课上传相同文件名 | 存储与索引仍独立，不覆盖其他资料。 |
| TC14 | 内部检索/工具/格式/复核失败，或上游不可用 | 尝试诚实的通用教学恢复；仍不可用则学习续接，额度/限流明确提示；不伪造引用或成功。 |
| TC15 | 资料中含提示注入语句 | 文档内容当作证据数据，不作为系统指令，不能泄露密钥。 |
| TC16 | 资料删除/学习数据导出删除 | 引用/索引不再使用已删资料，用户自己的历史可导出或删除。 |

这些用例应分别标记“自动测试通过”“人工 UI 验证通过”“真实模型验证通过”或“未验证”。自动测试通过不等同于学习效果研究或所有界面体验验收。

## 6. 数据与真实性边界

1. 手册 P0100—P0104 允许开源框架/公开模型/第三方工具，但要求说明来源、用途、使用方式；禁止未授权敏感数据、抄袭和虚假演示。
2. 当前生成、规划、出题、审核和视觉统一使用 Mimo，独立向量服务可选。用户已授权本地调用和验收；实际密钥仍只能后端读取，不进入前端、日志、README、测试快照或交付文档，配置示例保留空字段。
3. 若无四门商业教材的授权电子原件，可先内置清晰标识的原创课程参考资料/开放教材以及独立助教，提供授权教材上传路径；必须明确“参考资料”，不能把原创总结包装成出版社教材全文，不能声称已经实现用户要求的四本商业教材内置。
4. 报名表包含真实负责人及手机号。完整源材料用于本地需求证据；公开仓库、Demo、视频、技术文档删除不必要个人信息。
5. 学生学习掌握度只能由真实练习与明确规则产生，是系统估计，不是教师评定。没有真实用户调研、规模化使用或教学实验时不得宣称用户数、准确率、学习成绩提升、提效倍数或比赛得分。
6. 简历亮点应表述为实际实现的“可配置课程助教、来源可追溯检索、持久化学习闭环、可观测工作流、异常兜底”，有实测再补充延迟、命中率、覆盖率、成本。
